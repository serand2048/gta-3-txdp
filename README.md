# TXDP для GTA III 1.0 (PC)

ASI-плагин, переносящий секцию `txdp` из GTA SA. Проверен в игре: текстура, которой нет в TXD модели, берётся из родительского TXD.

## IDE
```
txdp
child_txd, parent_txd
end
```
Секцию можно класть в любой .ide (в том числе через modloader). Если текстуры нет в `child_txd`, она ищется в `parent_txd`, затем выше по цепочке (до 8 уровней).
Родитель должен лежать в gta3.img (или в modloader как `parent_txd.txd`) либо в `generic.txd`.

## Что делает плагин
- Читает секцию `txdp` через перехват `CFileLoader::LoadLine`.
- При сборке DFF (вызов `0x5AAE1B`, чтение текстуры материала) ищет промахнувшуюся текстуру у родителей.
- Стриминг: родитель запрашивается вместе с ребёнком (флаг DONT_REMOVE), а загрузка ребёнка откладывается,
  пока родитель не загружен (как в SA).
- Защита от зависания. Если TXD не читается (например, сохранён в формате Windows/D3D9, а не GTA III),
  игра сама перезапрашивает его бесконечно, и загрузка зависает без краша. Плагин подставляет такому TXD
  пустой словарь (его текстур не будет, но игра работает), а в лог пишет причину:
  - до чтения проверяется платформа первой текстуры (D3D9/Xbox/PS2 = неверный формат), так что RW такой файл не видит;
  - покрыты оба пути загрузки игры: `LoadTxd` (файлы до ~400 КБ) и `StartLoadTxd`/`FinishLoadTxd` (крупнее);
  - любой TXD, который 3 раза не загрузился или 20 раз подряд не прошёл `ConvertBufferToObject`, тоже получает пустой словарь.

## Совместимость со SkyGfx
SkyGfx патчит тот же вызов `0x5AAE1B` (откат на generic.txd). Плагин не борется с ним, а встаёт цепочкой:
сначала то, что стояло там раньше (SkyGfx: свой TXD, затем generic), затем родители из `txdp`.
В `txdp.log` при этом будет строка `texture read: 0x5AAE1B already patched by another plugin ... chaining`.
Следствие: текстура из generic.txd приоритетнее текстуры родителя.

## Сборка
1. plugin-sdk (installer / `PLUGIN_SDK_DIR`), VS2022, платформа Win32.

## Настройки и лог
Рядом с `txdp.asi` лежит `txdp.ini` (имя берётся от имени плагина):
```
[Main]
Log=0
```
`Log=1` включает лог `txdp.log`, он создаётся рядом с `.asi` и перезаписывается при каждом запуске.
`Log=0` (по умолчанию, в том числе если ini нет) - плагин ничего не пишет на диск.

Полезные строки лога:
- `txdp: A (n) -> B (m)` - разобранные пары (кроме `-> generic`)
- `request txd 'A': parent 'B'` - запрос родителя
- `defer txd 'A': waiting for parent 'B'` - ребёнок ждёт родителя
- `texture 'x' (txd 'A'): found in parent 'B'` - текстура найдена у родителя
- `... parent 'B' is loaded but has NO such texture` - в родителе нет текстуры с таким именем (дальше список его текстур)
- `FAILED (...) to load TXD` - TXD не читается; `TXD ... has the wrong format` - неверная платформа, пересохраните в формате GTA III
